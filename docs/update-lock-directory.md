# update.bat 락 디렉터리 적용 이유

## 적용 배경

`update.bat`은 버전 확인과 GitHub API 응답 처리를 위해 다음과 같은 임시 파일을 사용한다.

- `temp_version.txt`
- `temp_release_info.txt`

기존 방식에서는 임시 파일명이 고정되어 있어 `update.bat`을 동시에 여러 번 실행하면 다음 문제가 발생할 수 있다.

- 여러 프로세스가 같은 임시 파일에 동시에 쓰거나 읽음
- 한 프로세스가 파일을 읽는 동안 다른 프로세스가 삭제를 시도함
- `del temp_version.txt`에서 파일이 다른 프로세스에 의해 사용 중이라는 오류가 발생함
- 임시 파일 생성이 실패한 뒤 `for /f`가 파일을 읽으려 하여 파일을 찾을 수 없다는 오류가 발생함
- 다운로드와 기존 실행 파일 교체 작업이 동시에 진행될 수 있음

특히 `>` 리다이렉션은 명령의 출력을 파일로 연결할 뿐, 배치 파일 전체의 중복 실행을 막아주지는 않는다. 따라서 임시 파일을 사용하는 작업 전체를 하나의 실행 단위로 보호해야 한다.

## 선택한 방식

배치 파일 시작 시 `%TEMP%\github-exe-binary-update.lock` 디렉터리를 생성한다.

```bat
set "LOCK_DIR=%TEMP%\github-exe-binary-update.lock"
2>nul mkdir "%LOCK_DIR%"
if errorlevel 1 goto lock_failed
```

Windows에서 `mkdir`은 이미 같은 디렉터리가 존재하면 실패한다. 이를 이용해 먼저 디렉터리를 만든 프로세스만 작업을 계속하고, 나중에 실행된 프로세스는 이미 실행 중인 업데이트가 있다고 판단한다.

이 방식은 별도의 외부 프로그램이나 관리자 권한 없이 배치 파일에서 구현할 수 있고, 고정된 임시 파일을 사용하는 현재 구조에도 적용하기 쉽다.

## 동작 흐름

1. `%TEMP%` 아래에 락 디렉터리 생성을 시도한다.
2. 생성에 성공하면 버전 확인, API 조회, 다운로드, 검사, 파일 교체를 계속한다.
3. 이미 디렉터리가 존재하면 이전 실행이 비정상 종료되었을 가능성을 알리고, 락을 삭제하고 계속할지 사용자에게 묻는다.
4. 사용자가 삭제를 거부하면 기존 락을 보존한 채 중단한다.
5. 사용자가 삭제를 승인하면 기존 락을 제거하고 락 생성을 다시 시도한다.
6. 정상 종료 또는 업데이트 실패 시 자신이 만든 락 디렉터리를 삭제한다.
7. 락을 다시 생성하지 못하면 기존 락을 삭제하지 않고 중단한다.

락 실패 시에는 다음과 같이 사용자에게 안내한다.

```text
Another update process is already running.
Please wait for it to finish and try again.
```

## 파일 락과의 차이

이번에 적용한 것은 `temp_version.txt` 자체에 명시적인 파일 락을 거는 방식이 아니다. 배치 파일 전체의 중복 실행을 막는 실행 락이다.

`>` 리다이렉션은 출력 파일을 여는 동안 파일 핸들을 사용하지만, 명령이 끝나면 그 핸들이 닫힌다. 백신이나 인덱서가 잠시 파일을 검사할 수는 있어도, 배치 파일의 여러 단계가 동시에 실행되는 문제는 별도로 남는다. 락 디렉터리는 이 더 큰 범위의 동시 실행을 차단한다.

## 한계와 주의점

락 디렉터리는 배치 파일이 정상적으로 종료되거나 실패 경로를 거칠 때 삭제된다. 하지만 다음과 같이 배치 프로세스가 강제로 종료되면 락이 남을 수 있다.

- 콘솔 창을 강제로 닫은 경우
- 작업 관리자로 `cmd.exe`를 종료한 경우
- 시스템이 재부팅되거나 종료된 경우

다음 실행에서는 기존 락을 발견했다는 안내와 함께 삭제 여부를 묻는다.

```text
A previous update may not have exited cleanly.
Remove the existing lock and continue? (y/n):
```

실제로 다른 `update.bat` 프로세스가 실행 중이면 `n`을 선택해야 한다. 실행 중인 프로세스가 없고 이전 실행이 비정상 종료된 것이 확실할 때만 `y`를 선택한다.

업데이트 프로세스가 실행 중이지 않은 것이 확실한데도 락 삭제가 실패하면 다음 디렉터리를 확인할 수 있다.

```text
%TEMP%\github-exe-binary-update.lock
```

이 디렉터리를 직접 삭제하기 전에도 실제로 다른 `update.bat` 프로세스가 실행 중인지 확인해야 한다. 실행 중인 프로세스의 락을 삭제하면 중복 실행 방지 효과가 사라진다.

## 결론

락 디렉터리는 `temp_version.txt` 삭제 오류를 직접 숨기는 처리가 아니라, 그 오류의 주요 원인인 `update.bat` 중복 실행을 사전에 막는 장치다. 현재처럼 고정된 임시 파일을 사용하는 구조에서 파일 충돌과 실행 파일 교체 충돌을 줄이면서, 다른 프로세스가 사용 중인 파일을 강제로 종료하지 않고 안전하게 업데이트를 중단할 수 있다. 비정상 종료로 락이 남은 경우에도 자동으로 삭제하지 않고 사용자의 확인을 거치므로, 실제 실행 중인 업데이트를 실수로 허용하는 위험을 줄인다.
